# 逐章创作流程（所有写作模式共用）

> 本文件是逐章创作流程的**单一事实源**。串行模式、子Agent并行模式、Agent Teams 模式均执行本清单，各模式仅"如何认领下一章"不同（见 [phase3-writing.md](phase3-writing.md)）。
>
> `{skillBaseDir}` 为 skill 安装根目录占位符，由主 Agent 在派生子 Agent 时替换为实际绝对路径。

---

## 阶段 A：写前分析

1. **读取 `02-写作计划.json`** — 确认本章状态，读取本书 `minWordsPerChapter`（旧项目缺省 3000），将本章 `status` 置为 `"in_progress"`
2. **读取 `01-大纲.md`** — 找到当前章节的规划信息，提取：核心事件、承接上章、悬念钩子、出场人物、场景列表
3. **核对 `01-大纲.md` 设定与事实词典** — 核对本章将用到的设定名词：首现的按 [chapter-guide.md](../guides/chapter-guide.md)「新名词首现管理」带上下文线索；已介绍过的表述不得超出「读者已知」栏；到达「计划揭示」章节的必须兑现。**同时核对本章涉及的关键时间线顺序、核心因果源头**（如誓约发起人、旧恩情起因）与到期的伏笔（注意：人物不设具体年龄，正文严禁滥用生硬精确的数字描述）
4. **读取人物设定与当前处境** — 根据大纲中本章的「出场人物」，读取 `00-人物档案.md` 的性格核心、致命缺陷、说话风格/口头禅、恐惧/弱项、人物关系；同时读取 `99-章节摘要.md` 中上一章及这些人物在本章之前最近一次出场的摘要，承接其已知与误解、真实打算、情绪关系和行动条件。摘要缺项或有冲突时回查相关正文，不能用后章信息倒推人物当时已知
5. **读取上一章结尾原文** — 上一章文件名取自 `02-写作计划.json` 中上一章的 `filePath` 字段，读取其最后 500-800 字（第 1 章跳过），把握衔接语态和情绪落点
6. **读取 `03-文风基准.md`** — 重点读「基准段落」和「本书校准段落」（如有），作为本章文风的直接参照

> ⚠️ **动笔前最后读到的必须是正文语态文字（上一章结尾 + 基准段落），不要让大纲表格和摘要成为动笔前的最后上下文。**

---

## 阶段 B：撰写

7. **创建章节文件** — 统一存放在 `{projectPath}/正文/` 文件夹下，路径格式：`正文/第{XX}章-{章节标题}.md`（与 `02-写作计划.json` 中的 `filePath` 字段一致），使用 [chapter-template.md](../guides/chapter-template.md) 模板
8. **撰写章首引子** — 按大纲中本章的章首引子类型，参考 [hook-techniques.md](../guides/hook-techniques.md)「章首引子七式」，创作 50-150 字的引子文字
9. **撰写正文** — **每章达到本书 `minWordsPerChapter`，有约定范围时按范围创作**（若为 2.5万+ 番茄短故事模式，单章精修后也需保证全书总字数 ≥ 25000 字），硬性要求：
   - **前 200 字强吸引力**：承接上一章情境的同时，必须在 200 字内亮出人物眼前的具体危机、反常悬念或切身利害，抓牢读者继续阅读的动力（参考 [chapter-guide.md](../guides/chapter-guide.md) 开头技巧，不为套技巧硬造虚假危机）
   - **张力与详略节奏**：张力强度与章节用途匹配，重场戏给足动作与博弈细节，过渡场景利落带过，砍掉无意义的寒暄与环境堆砌（参考 [hook-techniques.md](../guides/hook-techniques.md) 悬念强度等级）
   - **对话要求**：对话比例服从场景需要，一段对话应推动事件、表现人物或影响关系；直说与潜台词按人物目的和处境选择（参考 [dialogue-writing.md](../guides/dialogue-writing.md)）
   - **有效变化**：本章在事件、认知或关系上产生有后续影响的变化；需要转折时由已有线索和人物选择引出，不为制造意外临时加事（参考 [chapter-guide.md](../guides/chapter-guide.md)「打破读者预期」）
   - **人物一致性与智商在线**：对话和行为必须严格符合阶段 A-4 提取的角色设定（性格核心、缺陷、说话风格），反派与配角具备正常智识与合理动机，严禁降智硬推剧情
   - 内容不足？使用 [content-expansion.md](../guides/content-expansion.md) 扩充技巧
10. **设置结尾钩子** — 按大纲中本章的悬念钩子设计 → [hook-techniques.md](../guides/hook-techniques.md)「悬念钩子十三式」

## 阶段 C：撰写后优化（十项必检自查清单）

11. **逐条执行「十项创作与审校自查清单」**（**严禁只用正则扫词走过场！必须逐场景、逐道具做现实常识反问，发现任一问题当场推翻改净**）：
    - **[1] 是否有逻辑谬误**：核查事件因果、时间线跨度前后一致、自报数量（如“两封信”“八个字”必须实地数清）、角色信息边界（不知道的事绝不说破）；**逐项核查现实制度与常识**：学制阶段统一（高中/大学绝不混写高数、早操、毕业答辩、保送/保研）、亲属辈分称谓准确（如小姑配小姑父）、法律与商业常识成立（人未去世遗嘱不生效、复写纸签名无法律效力）、食品保质期与物理常识合理（徒手不捏碎厚底玻璃杯、钢笔不戳穿厚讲义）。
    - **[2] 是否可以让读者代入**：检查主角眼前的处境、得失与情绪反应是否具体可感，读者能否理解其动机并产生共情或爽感期待。
    - **[3] 是否有违禁词**：排查涉政、违规犯罪敏感词、低俗暴力、封建迷信等平台审核违禁词与红线情节，用合规自然的表述替代。
    - **[4] 是否能在200字内吸引读者往下阅读**：重读本章开头前 200 字（及全书导读），确认直接切入具体冲突或反差处境，且**绝不夹带“买股文/反杀恶毒配角/掉马”等策划黑话或省略前因的不通顺缩略句**。
    - **[5] 是否用重复性描述词**：全文扫查是否存在高频复读的形容词、神态修饰词（如反复写“慢条斯理”“怯生生”“冷笑一声”）、重复小动作或雷同句式，具象修饰词避免重复，改用精准动词展现。
    - **[6] 是否有不知所云、晦涩难懂的自创名词**：剔除生造装腔作势的玄乎概念词、伪科技术语或莫名其妙的黑话，设定表达通俗直白，新名词首现必带清晰上下文线索。
    - **[7] 是否有经典AI用句，记得好好说话**：彻底清除“然而/与此同时/不禁/油然而生/这一刻/仿佛/不是A而是B/没有A没有B/不着痕迹/唇角勾起一抹弧度”等AI套话；**彻底删去任何预设读者质疑、替角色行为打补丁找补的解释性/防御性旁白**；删去动作对话已表达清楚后的同义心理总结，好好说人话。
    - **[8] 是否有过于精确、不必要的数字描写**：严禁出现具体年龄，严禁出现精确百分比、精确米数/寸数/秒数/度数（如“鞠躬九十度”“挪了半寸”“百分之十”）等机械数字，改用符合人类叙事直觉的自然模糊表述。
    - **[9] 是否详略得当，没有无意义的描写**：删去不推动情节、不揭示人物、不营造张力的过场寒暄、凑字数景物描写与已知信息复述。
    - **[10] 是否有不符合人设的情节或降智情节**：**严禁顺着大纲里的弱智设定硬圆**！对每个桥段反问“现实里正常成年人/财阀/名校机构会这么干吗”——杜绝“学校有医务室学生还背药箱上学”“富豪买不起普通糖浆或成年人被家里禁糖”“反派手下接陌生电话直接自爆伪造公章”“名校教务处不查公网作废假章”等一切降智凑剧情写法。
12. **字数检查** — 必须使用脚本检查：

    ```bash
    node "{skillBaseDir}/scripts/check_chapter_wordcount.mjs" "{章节文件绝对路径}" {minWordsPerChapter} --json
    ```

    退出码：0=达标，1=不足，2=错误。读取 `results[].word_count` 填入写作计划的 `wordCount`。`{minWordsPerChapter}` 使用写作计划中本书的字数下限。

    低于本书字数下限 → 使用 [content-expansion.md](../guides/content-expansion.md) 扩充有效情节细节后复检（扩充内容同样须符合十项自查，不得注水）

## 阶段 D：收尾

13. **生成章节摘要** — 在 `99-章节摘要.md` 按章号保存本章摘要（约 300–500 字），写清“发生了什么，以及留下了什么后果”，供后续直接续写：
    - **事件与后果**：只写关键事件及其造成的变化，不流水账复述场景，不用“关系更复杂”“气氛更紧张”等空泛总结
    - **人物处境**：对影响后文的角色，区分已知、尚未知与误以为；区分公开表态、真实打算与已经完成的行动。记录未消解的情绪和关系变化及原因，避免下章自动和解或恢复信任
    - **行动条件与未了事项**：保留影响后续的时间、位置、伤势、物品归属，以及尚未兑现的承诺、代价、疑问和伏笔；长期事实可引用词典，不重复抄录
    - 只记正文已确立的事实，未确定的标明“未明”；关键变化注明来源场景。旧状态未变化可引用此前章号；改稿时更新原章摘要，不追加互相矛盾的记录。合计控制在约 300–500 字，无关项省略，不为填字段凑字

    **摘要示例（节选，非完整摘要）**：哥哥发现妹妹撒谎，但仍不知道信件内容；妹妹误以为他已经看过信。钥匙由妹妹带走（来源：章末门口争执）。双方未和解。哥哥嘴上答应停查，实际决定跟踪，尚未行动。下章须承接误判、信任裂痕和钥匙归属，不能把合作计划写成已经和解

    **写入方式**：先读取本章预建小节，用 Edit 在 `## 第{XX}章 {标题}` 下写一到数段摘要，不设固定分栏、不追加同章副本。框架由主 Agent 在规划或恢复开写前调用 [规划阶段的摘要脚本](phase2-planning.md) 创建或补齐；Edit 冲突时重读后重试。

14. **更新设定与事实词典** — 本章首现的设定名词、关键时间线先后事实、核心因果源头与伏笔线/标志性桥段，登记进 `01-大纲.md` 设定与事实词典；本章有揭示兑现的名词或伏笔，更新其「读者已知」栏；重复使用的桥段在原登记行追加章号，检查重复是否改变了处境、关系或含义；仅复述同一效果的桥段删减或调整
15. **更新 `02-写作计划.json`** — 正文检查通过且本章有效摘要已保存到正式文件后，将 `status` 设为 `"completed"`，填入 `wordCount` 与 `wordCountPass`。空标题、注释和占位不满足完成条件。Edit 冲突时重读文件后重试。
16. **第一章文风校准（仅第 1 章）** — 从定稿的第 1 章选取 1-2 个最佳段落（建议：开头钩子段 + 一个高张力段，合计 600-1000 字），追加到 `03-文风基准.md` 的「本书校准段落」区，作为后续所有章节的文风锚点

---

完成后，按当前写作模式认领下一章（详见 [phase3-writing.md](phase3-writing.md)）。
