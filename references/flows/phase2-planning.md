# 第二阶段：规划 + 二次确认

> **前置条件**：本阶段使用 Phase 1 Layer 3 用户确认的小说标题。标题信息从对话上下文中获取，用于命名项目目录、写入大纲文件头和写作计划 JSON。

执行以下步骤：

1. **询问存放地址并创建项目文件夹**：在创建项目前，先使用 `AskUserQuestion`（或直接询问）向用户确认小说项目的存放目录（默认推荐 `./小说/{Layer 3 确认的标题}/`，文件夹名**只保留小说名，不带时间戳**）。**多章模式**在项目文件夹内创建 `正文/` 子文件夹，所有章节正文文件统一存放在 `正文/` 目录下；**单文件短篇模式**（全文写在一个 `.md` 文件里的短篇）**不要创建 `正文/` 子文件夹**，直接将正文文件存放在 `./小说/{小说名称}/{小说名称}.md`（严禁命名为 `全文.md`）。
2. **生成人物档案**：创建 `00-人物档案.md`，使用 [character-template.md](../guides/character-template.md) 模板，参考 [character-building.md](../guides/character-building.md) 创建主角、反派、配角档案。**人物档案必须详细**：每个角色的性格核心、致命缺陷、说话风格/口头禅、恐惧/弱项、背景故事都要具体到可以直接指导写作的程度（严禁设定具体年龄或机械数字；**严禁使用网文烂大街模板重名，男女主及核心配角起名必须避开工作区已有小说角色姓名及网文高频撞名库**）。
3. **生成大纲**：创建 `01-大纲.md`，使用 [outline-template.md](../guides/outline-template.md) 模板，参考 [plot-structures.md](../guides/plot-structures.md) 填入完整的章节规划。**大纲必须以人物驱动情节** 参照 `00-人物档案.md`，确保情节服务于人物成长弧线。
3.5. **生成文风基准**：创建 `03-文风基准.md`，包含四部分：
   - **文风指纹**：对话使用倾向、句子节奏、段落呼吸、叙述距离、描写倾向，基于 Layer 2 已有的基调/风格参考/目标读者生成；用正文范例说明，不预设统一对话比例或句长限制
   - **基准段落**：2 段体现目标文风的正文范例（各 500-800 字）。用户在问答中提供过喜欢的作品片段则直接采用
   - **负面清单**：引用 [chapter-guide.md](../guides/chapter-guide.md)「AI 写作痕迹清除」与十项创作自查铁律条目
   - **本书校准段落**：（初始为空，第 1 章完成后由 Phase 3 回填）
4. **生成写作计划**：创建 `02-写作计划.json`，基于大纲内容填充，结构如下：
   ```json
   {
     "version": 1,
     "novelName": "[小说名称]",
     "projectPath": "./小说/[小说名称]",
     "totalChapters": [章节数],
     "minWordsPerChapter": [用户确认的每章最低字数],
     "maxWordsPerChapter": null,
     "createdAt": "[ISO时间]",
     "updatedAt": "[ISO时间]",
     "status": "planning",
     "writingMode": "[serial|subagent-parallel|agent-teams|viral-short-12k|forum-style]",
     "chapters": [
       {
         "chapterNumber": 1,
         "title": "[章节标题]",
         "filePath": "正文/第01章-[章节标题].md",
         "status": "pending",
         "wordCount": null,
         "wordCountPass": null,
         "retryCount": 0
       }
     ]
   }
   ```

   `chapterNumber`、`title` 与大纲章节规划一致；写作计划记录状态、字数和重试次数，章节摘要保存到独立文件。

   > **💬 纯正论坛体模式（`forum-style`）专属规划规则**：
   > 当创作论坛体小说时，**以能够完整清晰地描述出整个事件作为唯一评判标准，无任何字数要求或限制**：
   > - `01-大纲.md` 中不设目标字数限制，按事件推进脉络规划楼层阶段即可。
   > - `02-写作计划.json` 中设置 `"totalChapters": 1`、`"minWordsPerChapter": null`、`"maxWordsPerChapter": null`、`"writingMode": "forum-style"`，单章 `filePath` 设为 `"{小说名称}.md"`。

   > **🔥 12000字一镜到底爆款短篇模式（`viral-short-12k`）专属规划规则**：
   > 当用户在 Q8 选择「12000字一镜到底爆款短篇」时：
   > - `01-大纲.md` 采用**三幕精确规划**（第一幕 2000字：前200字强钩子+人物建立+推动事件；第二幕 8500字：多线发展+6000字中点重大转折+困境升级+3~4个情感爆点；第三幕 1500字：高潮对决+最后1000字终极揭示+多重收束+价值升华），并规划好 3 个大悬念与每 800 字一个的小悬念节奏点。
   > - `02-写作计划.json` 中设置 `"totalChapters": 1`、`"minWordsPerChapter": 11500`、`"maxWordsPerChapter": 12500`、`"writingMode": "viral-short-12k"`，不创建 `正文/` 子文件夹，单章 `filePath` 设为 `"{小说名称}.md"`（即直接放在 `./小说/{小说名称}/{小说名称}.md`，不要放在 `全文.md` 里）。
   > - 确认规划后无需再询问串行/并行模式，直接进入第三阶段的「12000字一镜到底爆款短篇模式」创作。

5. **创建章节摘要文件**（多章模式执行）：写作计划保存后，调用安装目录的绝对路径：
   ```bash
   node "{skillBaseDir}/scripts/init_chapter_summaries.mjs" "{项目目录绝对路径}" --json
   ```
   脚本读取写作计划，预建全部 `## 第{XX}章 {标题}` 小节，标题下留空；再次运行只补缺失标题，保留已有内容。退出码：0=成功，1=框架冲突（见 `issues`），2=参数或文件错误。

6. **规划文档与基准段落「十项自查」（呈现给用户前必做）**：
   对照 `SKILL.md` 的**「十项创作与审校自查铁律」**逐项检查 `00-人物档案.md`、`01-大纲.md`、`03-文风基准.md`：
   1. 是否有逻辑谬误（设定机制、排查博弈、因果时间线是否严丝合缝）
   2. 是否可以让读者代入（主角痛点、目标与情绪抓手是否具体）
   3. 是否有违禁词（排查平台审核敏感词与违规擦边表述）
   4. 是否能在200字内吸引读者往下阅读（检查开篇切入点与基准段落前 200 字吸引力）
   5. 是否用重复性描述词（清理档案、大纲与范例中重复的形容词与神态词）
   6. 是否有不知所云、晦涩难懂的自创名词（把装腔作势的伪科技/玄乎造词替换为直白人话）
   7. 是否有经典AI用句，记得好好说话（清除基准段落中的AI套话、翻译腔与解释性旁白）
   8. 是否有过于精确、不必要的数字描写（删除具体年龄、精确百分比/寸数/度数/倍数等生硬数字）
   9. 是否详略得当，没有无意义的描写（确保每章核心事件饱满不注水）
   10. 是否有不符合人设的情节或降智情节（确保主角、配角、反派行动符合人设与智商上限）

完成后，执行以下两步：

**1. 展示规划摘要并请求确认**

向用户展示规划摘要（小说名称、总章数、每章最低字数、全书最低字数、主要人物、文风基准来源）并请求确认。

**2. 写作模式选择**（用户确认规划后）

使用 `AskUserQuestion` 询问：

```
Question: 选择写作模式
Options:
- 逐章串行（主 Agent 自己逐章写，全程无中断，适合短中篇）
- 子Agent并行（分批派生子 Agent 并行写作，大纲驱动连贯性，适合中长篇）
- Agent Teams（Claude Code 多 Agent 协作模式，Agent 间可通讯，需手动开启）
```

用户选择后：
- 更新 `02-写作计划.json` 的 `writingMode` 字段
- 更新 `status` 为 `"in_progress"`
- 进入第三阶段：疯狂创作 → 详见 [phase3-writing.md](phase3-writing.md)
