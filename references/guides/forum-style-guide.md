# 论坛体小说创作与小红书手绘风出图方法论

本指南定义了「纯正论坛体小说」的文本创作规范与小红书手绘草稿风固定 UI 渲染方法论。当用户要求创作**论坛体 / 树洞体 / 贴吧盖楼体**小说，或要求将论坛体导出为小红书图片时，严格执行本指南。

---

## 一、纯正论坛体文本创作四大核心规范

### 1. 100% 纯盖楼结构（零帖外旁白、零小说式描述）
- **从第一行到最后一行，全篇必须在同一个论坛帖（`0L 主楼` 至 `XXL 封帖`）中通过盖楼回复推进**。
- **严禁出现任何帖外旁白、场景描写、心理独白或小说叙事段落**；也不要插入浮夸生硬的“全塔/全服金色广播弹窗”。所有剧情冲突与结局，全部通过楼主回帖、层主吃瓜、知情人侧面爆料与正主小号下场自然呈现。
- **标准 Markdown 楼层格式**（与渲染脚本 100% 咬合）：
  ```markdown
  **【版块名称 > 子版块名称】**

  **标题：【求助】帖子标题内容**

  ---

  **【0L 楼主昵称（楼主）】**

  主楼正文段落……

  ---

  **【1L 匿名用户】**

  回帖内容……
  ```

### 2. 极简口语 + 侧面留白拼图（严禁镜头级细节描写与同质化水词）
- **去小说腔**：发帖人和回帖人只用最简单直白的日常口语陈述**表面现象与结果**，绝不写小说式的镜头细节描写或修辞渲染。
- **严控「哈哈哈哈 / 救命 / 卧槽 / 笑死」等感叹词频率与位置**：真实论坛里不同层主说话习惯各异，严禁让多个楼层连续以「哈哈哈哈哈哈救命！」「卧槽！」作为第一句开头。此类感叹词全文只需少量点缀，且应分散放在段中或句尾，更多通过具体吐槽、反问、引用或冷幽默来体现情绪。
- **侧面拼图手法**：楼主只陈述自己看到的表象（往往带着视角局限或迟钝误解），由楼下的吃瓜网友与知情层主从侧面补充信息，让读者在楼层互动中自己拼凑出完整真相与人物情感张力。

### 3. 全员匿名与零真名暴露（代称化语境）
- 在真实的匿名树洞帖里，**通篇下来绝不爆出任何一个角色的真名或姓氏**。
- **ID 规范**：
  - **楼主**：固定一个符合人设的昵称，如 `柑橘软糖（楼主）`。
  - **正主/关键角色小号**：使用系统默认风格或带数字纪念意义的代号（如 `用户0719`），发言简短克制。
  - **其余所有围观群众与知情同事**：ID 统一为 `匿名用户`（知情同事多次出现时可在正文开头写「我是22楼！」认领身份）。
- **人物指代**：楼内统一使用代称交流（如「楼主」「顶楼那位执行官」「那位活阎王」「匹配中心那位评审官」）。

### 4. 无任何字数限制，以完整清晰描述事件为唯一标准（铁律）
- **论坛体以能够完整、清晰地描述出整个事件作为唯一评判标准，不会有任何字数要求或上下限限制。**
- 在问答、规划、写作与校验全流程中，**严禁向用户询问论坛体篇幅/字数规模**，严禁套用 3000 字或 12000 字等任何字数指标（`02-写作计划.json` 中 `minWordsPerChapter` 与 `maxWordsPerChapter` 均设为 `null`），绝不为凑字数注水，也绝不为卡字数删减有效剧情。

## 二、小红书论坛体「OC 手绘风 / 同人专属 UI」双轨固定 UI 渲染方法论

配套脚本位置（模块化多品类架构）：
- 技能内置：`{skillBaseDir}/scripts/render_xhs_forum.js` + `{skillBaseDir}/scripts/themes/{index.js, common.js, oc.js, glory.js}`
- 工作区快捷入口：`./工具/生成小红书论坛体图片.js` + `./工具/themes/{index.js, common.js, oc.js, glory.js}`

> **⚠️ 铁律一：先交由用户审阅/手改 `.md` 文档，严禁完稿后擅自抢跑生成图片！**
> 1. 论坛体小说 `.md` 正文创作完成后，**绝对禁止立即自动运行脚本生成封面或预览图片**！
> 2. 必须先向用户交付 `.md` 文档，让用户在编辑器中确认文字并手工修改；**只有当用户明确告知“修改完成 / 可以设计图片和封面了”之后，Agent 才可重新 `Read` 最新磁盘上的 `.md` 文件（严防覆盖用户手改内容），进入图片与封面设计环节。**
>
> **⚠️ 铁律二：出图前必须先向用户询问视觉设计，严禁将「手绘草稿手账风」用于任何同人作品！**
> 1. **在生成任何图片之前，必须先向用户询问**：主动与用户沟通确认本次图片与封面的 UI 风格、主题配色及专属元素设计，**绝不能未经询问直接套用默认模板出图**。
> 2. **OC 原创作品（`themes/oc.js`）**：「手绘草稿手账风 UI」（默认 `warm-orange` 暖杏甜橘等 7 套手绘水彩/马克笔色系）**严格仅限 OC（Original Character 原创角色）相关内容使用**！
> 3. **同人向作品（如《全职高手》`themes/glory.js`、《龙族》守夜人论坛等）**：**绝对禁止使用手绘草稿风**！同人图片与封面必须带有对应原著 IP 的标志性视觉元素（例如：《全职高手》同人一律固定采用「荣耀官方论坛·深空暗金电竞风 UI」`--theme=glory-gold`；《龙族》同人必须带有卡塞尔学院世界树半朽校徽、守夜人论坛专属终端元素等）。若当前同人 IP 尚未建立专属主题模块，必须先与用户确认设计方案并在 `themes/` 下新建该 IP 的专属主题模块，再在 `themes/index.js` 注册。

### 1. 手机端原生大字护眼排版与《全职高手》固定标准封面规范
- **《全职高手》同人封面（`00-封面.png`）固定标准格式（铁律）**：
  - 凡是《全职高手》同人作品，封面一律固定采用**「纯色深空黑底（`#080C15` 零渐变）+ 双层鎏金画框（`.glory-cover-outer-frame`）+ 顶部纯矢量荣耀双翼双剑徽章 + `GLORY OFFICIAL FORUM · 神之领域` + 中央红底标签 `#818 灌水区精华热帖` + 双行实色大标题（上行纯白 `#FFFFFF` `35pt`、下行纯金 `#F5C451` `40pt`）+ 48px 短金线 + 居中精华引文 + 底部 `楼主：{楼主名}` 与 `{回帖数} REPLIES >>>`」**格式！
  - 后续所有《全职高手》论坛体封面严格保持该版式不变，仅动态替换标题文字、精华引文与楼主名。
- **原生逻辑视口与动态自适应高度（铁律）**：画布宽度固定为 `375px`（`deviceScaleFactor: 3` 超清渲染为 `1125px` 宽），**仅保留最大高度限制 `max-height: 500px`（`1500px`），不锁定死固定高度**（除封面 `00-封面.png` 保持 `375 × 500` 标准尺寸外，所有正文图片 `height: auto; max-height: 500px`——当某页楼层未占满最大高度时，允许图片自动收缩高度贴合内容，严禁在页尾留出大块空白）。
- **大字号与全宽对齐**：正文字号默认设为 **`15.5pt`**（每行仅 19～21 个汉字，加 `0.12px` 微描边防压缩发虚）；取消正文左侧头像缩进浪费，采用全宽左对齐，确保在小红书信息流里不点大图也能轻松阅读。
- **自然段级零截断分页与防末行裁切铁律**：通过无头浏览器实测每个楼层表头与每一自然段的真实 DOM 高度（测量容器 `#measure-card` 必须设为 `max-height: none; overflow: visible;`，`.floors-container` 必须设为 `flex: 0 0 auto; overflow: visible;` 禁止 flex-shrink 压缩，上下预留 `24px` 安全余量且严禁 `+5px`/`+3px` 超限硬塞），彻底杜绝楼层最后一行文字被裁切。
- **`preview.html` 单列纵向预览规范**：生成的 `preview.html` 必须采用**一列一张图（`flex-direction: column; align-items: center;`）**纵向排布，并在最上方包含封面图。

### 2. 双轨视觉设计体系
- **轨道 A：同人向 ·《全职高手》专属「荣耀官方论坛·深空暗金电竞风 UI」（`--theme=glory-gold`）**：
  - **触发条件**：凡是《全职高手》同人作品（版块含「荣耀」或正文含神之领域/全职角色与公会），一律启用 `glory-gold` 电竞风 UI。
  - **核心视觉元素**：深空暗蓝渐变背景 + 中央大幅荣耀银武/双翼徽章正版水印 + 顶部 `GLORY` 金色徽章导航栏 + 六边形电竞装甲头像 + 各大公会阵营胶囊标签 + 无外框细金线分隔楼层 + 内嵌黑底白字海报组件支持。
- **轨道 B：OC 原创（Original Character）专属「去 AI 感 · 手绘草稿手账风 UI」**：
  - **适用范围**：仅用于用户原创角色（OC）与原创世界观（如向导哨兵、都市脑洞等）论坛体。
  - **核心手绘视觉元素**：
    - **方格草稿本底纹**：暖色调方格手账纸背景 + 顶部手写虚线眉栏。
    - **SVG 钢笔微抖动线框**：通过全局 SVG `<feTurbulence>` + `<feDisplacementMap>` 滤镜（`#sketch-wobble`）单独作用于卡片边框、和纸胶带与印章层，呈现真实钢笔手绘的不规则线条感，而文字层保持 100% 清晰锐利。
    - **错位马克笔硬阴影**：卡片右下方采用手账本平涂错位硬色块阴影，配合顶部半透明斜纹手绘和纸胶带（Washi Tape）。
    - **荧光笔半涂抹高亮**：正文中所有 `「……」` 关键台词自动渲染为马克笔半高涂抹高亮效果。
    - **简笔画涂鸦头像与印章**：内置纯钢笔手绘简笔画头像（楼主脸红小柑橘、男主小号速写黑豹、匿名网友 4 款简笔画吃瓜小人自动轮换）与倾斜手绘印章标签（仅楼主显示 `[楼主]`、新注册特殊小号显示 `[刚注册]`，`匿名用户` 后面绝不挂载任何身份/部门 tag）。

### 4. 「用户改定 `.md` → 询问视觉方案 → 先预览 1 张 → 确认后全量生成并同步私密图库」工作流铁律（必守）
- **论坛体图片与 `.md` 原稿统一归档至 GitHub 私密仓库规则**：
  - 所有论坛体小说生成的小红书图片（含 `00-封面.png`、`01.png ~ XX.png`、`preview.html`）以及小说源目录下的所有 **`.md` 正文/设定文件与 `.json` 文件**，**统一归档在本地私密图库仓库 `./小红书论坛体图库/{小说名称}/` 对应的文件夹下**，并自动上传至 GitHub 私密仓库：`https://github.com/Kx-Chen-99/my-novels.git`（分支：`main`）。
  - 当某篇作品已发布至小红书或已完结、用户要求删除本地对应文件夹时：先确保其全套图片与 `.md` 文件已 push 到 GitHub 私密仓库 `Kx-Chen-99/my-novels`，随后通过 `git -C "./小红书论坛体图库" sparse-checkout` 将该文件夹从本地检出树中排除并删除 `./小说/{小说名称}/`，既彻底清理本地目录，又确保 GitHub 云端永久保留该作品的完整图文与 `.md` 原稿（后续提交不会误删云端文件）。
- **四步标准工作流**：
  1. **第零步（等待用户审阅并手改 `.md`）**：正文写完后只交付 `.md`，等待用户在编辑器内修改完毕并明确指令开始做图后，重新 `Read` 最新 `.md` 文件。
  2. **第一步（出图前强制询问视觉与封面设计）**：向用户询问确认本次使用的 UI 主题（OC 选具体手绘色系；同人作品确认对应 IP 的专属元素、配色与封面设计，**严禁将手绘风用于同人作品**）。
  3. **第二步（快速预览）**：先带 `--first-only`（或 `--page=N`）参数运行脚本，仅生成封面与第 1 页预览图展示给用户确认效果（单页预览不会触发 git push）：
     ```bash
     node {skillBaseDir}/scripts/render_xhs_forum.js "./小说/[小说名称]/[小说名称].md" --theme=[确认的主题ID] --first-only --with-cover
     ```
  4. **第三步（确认后全量导出并自动上传私密仓库）**：待用户明确表示确认满意后，去掉 `--first-only` 运行全量生成；脚本会自动将全套图片及 `.md`/`.json` 原稿同步至 `./小红书论坛体图库/[小说名称]/`，并自动执行 `git add`、`git commit` 与 `git push origin main` 上传至 GitHub 私密仓库 `Kx-Chen-99/my-novels`：
     ```bash
     node {skillBaseDir}/scripts/render_xhs_forum.js "./小说/[小说名称]/[小说名称].md" --theme=[确认的主题ID] --with-cover --push
     ```
